# Domain Docs

Use a single domain context for this repository.

Before exploring, read `CONTEXT.md` and relevant ADRs under `docs/adr/` when they exist. Proceed silently when they do not.

Use glossary terms consistently in issues, specs, tests, and code. Surface conflicts with existing ADRs rather than silently overriding them.

The domain-modeling skill creates these files lazily when terminology or durable architectural decisions are resolved.
